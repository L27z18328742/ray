# 把训练 worker 一个个启动起来

> 阅读目标：追踪 rank 0 的地址如何到达其他 worker，并分清 Ray PG 与 PyTorch process group。状态：已展开。

## 已经有资源，下一步才是创建进程

继续两张训练卡的例子。`world_size = num_nodes × num_gpus_per_node = 2`，所以要启动两个训练 Ray Actor。每个 Actor 长期持有自己的模型分片或副本、optimizer 状态和分布式通信状态。

本章主链：**create_training_models → create_actor_model → RayTrainGroup.create → _allocate_gpus_for_actor → 构造所有 Actor → init 所有 Actor → 连接 manager**。

## 先看四个初始化参数

| 参数 | 两 worker 示例 | 作用 |
|---|---|---|
| `world_size` | 都是 2 | 训练进程组总进程数 |
| `rank` | 0、1 | 当前进程在训练组中的全局编号 |
| `master_addr` | rank 0 所在节点地址 | 进程组初始化的会合地址 |
| `master_port` | rank 0 查找的空闲端口 | 配合地址完成会合 |

这里的 master 与 Ray head 不是同一个概念。Ray 集群的控制节点负责 Ray 服务；训练的 `MASTER_ADDR` 是此组训练 worker 建立 PyTorch 通信时使用的地址。

## rank 0 为什么先被询问

阅读 [RayTrainGroup._allocate_gpus_for_actor](source:slime/ray/actor_group.py#RayTrainGroup._allocate_gpus_for_actor)。先选择默认 `MegatronTrainRayActor` 实现，再包装成远程类。创建循环的核心可以简化为：

```python
master_addr, master_port = None, None
for rank in range(world_size):
    actor = TrainRayActor.options(...).remote(
        world_size, rank, master_addr, master_port
    )
    if rank == 0:
        master_addr, master_port = ray.get(
            actor.get_master_addr_and_port.remote()
        )
    self._actor_handlers.append(actor)
```

rank 0 的构造函数发现没有 master 地址，就选择自己节点的 IP 与空闲端口。driver 等待拿到它，再把同样的地址端口传给 rank 1。**此时还没有让 rank 0 单独完成全部分布式初始化。**否则它可能一直等尚未创建的同伴。

随后 `create()` 才对所有 worker 提交 `init.remote()`，一次性 `ray.get` 这组引用。这种“先创建所有成员，再同时初始化”对需要互相等待的分布式系统很重要。

## 从 Ray 的 GPU ID 到训练设备

[TrainRayActor.__init__](source:slime/ray/train_actor.py#TrainRayActor.__init__)设置 `MASTER_ADDR / MASTER_PORT / WORLD_SIZE / RANK / LOCAL_RANK`。本版本通过 `get_local_gpu_id()` 调用 accelerator 的可见设备映射，不应简单把 `rank` 当本机 GPU ID。

训练 Actor 的 runtime env 设置了一组 `RAY_EXPERIMENTAL_NOSET_*_VISIBLE_DEVICES` 开关。读这个项目时，要同时查看 Ray 分配的 GPU ID、进程可见设备和显式设备选择，不能直接套“每个 Actor 都只能看到一个 cuda:0”的直觉。

资源也有两层：PG bundle 预留的是 1 GPU；[allocate_train_group](source:slime/ray/placement_group.py#allocate_train_group)实际传入 `num_gpus_per_actor=0.4`，worker 的 `.options()` 覆盖了远程类上初始的 1 GPU 声明。这是逻辑资源记账，不是显存的 40% 硬上限。第 10 章专门解释。

## 进入真正的分布式训练初始化

1. [RayTrainGroup.create](source:slime/ray/actor_group.py#RayTrainGroup.create)：输入 manager handle，创建 worker 并等待 `init`，返回起始轮次列表。
2. [MegatronTrainRayActor.init](source:slime/backends/megatron_utils/actor.py#MegatronTrainRayActor.init)：调用父类，再初始化 Megatron 和模型 / optimizer，得到 checkpoint 对应的起始轮次。
3. [TrainRayActor.init](source:slime/ray/train_actor.py#TrainRayActor.init)：设置实际设备，调用 `dist.init_process_group`，并初始化 Gloo 辅助组。
4. [TrainRayActor.set_rollout_manager](source:slime/ray/train_actor.py#TrainRayActor.set_rollout_manager)：保存 manager handle；训练 rank 0 把 `train_parallel_config` 发给 manager，告诉它后续按多少个 DP 分片准备数据。
5. [create_training_models](source:slime/ray/placement_group.py#create_training_models)：要求返回的起始轮次一致，必要时恢复数据源进度，最终交还模型组给 driver。

## 两种 group 不是同一个东西

| 名称 | 管理什么 | 代表操作 |
|---|---|---|
| Ray Placement Group | 一组资源的放置与预留 | `placement_group(...)` |
| PyTorch Process Group | 一组训练进程之间的通信 | `dist.init_process_group(...)` |
| slime RayTrainGroup | driver 里的 worker handle 集合 | `async_train / update_weights` |

选读 [RayActor](source:slime/ray/ray_actor.py#RayActor)，它只提供地址、端口等小工具，本身没有 `@ray.remote`。暂缓 Megatron 并行组内部算法；这里以“初始化完成后可以一起训练”为接口边界。
